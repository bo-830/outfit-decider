# DESIGN · 出门穿什么（outfit-decider）

本文件是视觉与交互的落地说明，与 `src/ui/theme.js` 的令牌**逐字对应**。
方向来源：`docs/design/style-explorer.html`（第 01 轮两方向对比页）→ Lead 拍板
**A「晨光试衣间」作主方向 + B「冷光决策台」的读数语言**（B 的深色底与全英仪器文案不采用）。

---

## 1. 用户任务与首屏

**用户是谁**：早上出门前 1–3 分钟、通常单手、可能站在衣柜或窗边的人。她的问题不是"我的衣橱有什么"，
而是"这几套里穿哪套"，而且怕穿错。

**首屏（上传页）她来做什么**：选 1–4 张穿搭照 → 点场合/天气/风格 → 补一句 → 选一个问题 → 点「开始快速评分」。

**首屏结构**：内容先行。没有 App 标题栏、没有大 banner、没有插画。第一屏从上到下就是
标题一行 → **2×2 照片网格**（照片是唯一主角）→ 场合 chips → 底部常驻 CTA。
选图之前不出现任何装饰性内容。

**北极星**：像早上在试衣间里试完四条搭配、把照片摊在亚麻桌布上挑一套——纸与布的手感，
安静、可信、不喧闹。分数是量出来的读数，不是拍脑袋的形容。

## 3. 读数语言（从方向 B 搬过来的部分）

B 的语言被翻译成中文与纸感，不搬它的深色底与英文铭牌：

1. **等宽名次**：`01 / 02 / 03 / 04`（`MONO` 字族 + tabular），第 1 名的名次用 `accent` 着色。
2. **名次条**（`NameplateRow`）：结果页列表上方一行 `名次 · 穿搭 · 综合分` ／ 右侧 `3/4 套有效`，
   一眼说清这张表在比什么。
3. **软尺刻度**（`ScoreScale`，本 App 的辨识点）：每个维度是 0–5 的刻度尺（6 个刻度 + 基线），
   指针落在读数位置。**不是进度条**——读数是量出来的，指针是量出来的结果。
   与你问题最相关的维度（`relevance`）指针加长并用 `accent` 着色。
4. **双系统同屏对比**：两栏面板，左栏 `[快速评分]`（大分数 + 六维读数 + 前三名），
   右栏 `[深度分析]`（星级 + 一句话理由 + 结论块 + 一条具体建议）。
   两栏都在 390 宽度内完整可见，不靠横向滚动藏住任何一栏。

## 4. 屏幕与关键状态

| 屏幕 | 结构 | 关键状态 |

### 4.5 三档引擎模式与结论来源（v1.5 · SPEC §3.9b/§3.9c）

**为什么设置页要分成两组**：`laya_review` 与 `multimodal_only` 都需要一个**能看图的模型**，
而它与决策模型是**两个不同的服务**（不同供方、不同地址、不同 Key）。
混成一组会让用户以为"配一个就够"，所以两块各有自己的地址 / 模型名 / Key / 测试按钮与结果行。

**设置页 · 引擎模式**（取值与顺序来自 `src/engine/api.js` 的 `ENGINE_MODES`，界面不另写一份数组）

| 锚点 | 标题 | 副文案 |
|---|---|---|
| `engine-mode-laya-only` | 只用 Laya 本地模型 | 不花钱、离线可用；判断力实测偏弱 |
| `engine-mode-laya-review`（默认，带「默认」小标签） | Laya + 多模态纠正 | 先用本地模型打分，再由能看图的模型纠正 |
| `engine-mode-multimodal-only` | 只用多模态模型 | 跳过本地模型，直接由能看图的模型判断 |

选中语言沿用 chip 的「墨色实心」：未选中 `surface` 底 + `border` 描边 + `textDim` 文字；
选中 `text` 实心底 + `surface` 标题（16.2:1）+ `surfaceAlt` 副文案（13.5:1）。
原 JEv/Laya 二选一改名**「决策模型来源」**并统一成同一套选中语言——
一屏两个模式选择器不能有两套视觉，否则用户要重新学一次"选中长什么样"。

**设置页 · 能看图的模型**（`engine-vision-baseurl` / `engine-vision-model` / `engine-vision-key` / `btn-save-vision-key` / `btn-test-vision` / `test-vision-result`）

- 分组副标题：**本地模型看不了照片。这一组负责把照片变成描述、并在需要时纠正分数。**
- 模型名是自由输入（无白名单、无下拉）：端点各家命名不同，锁死等于把用户关在门外。
- `laya_only` 时标题降为次级墨色并挂一枚 `surfaceAlt` 的「当前档位用不到这一组」标记；
  输入保持**满对比可读**（不整组降透明度——55% 会把标签压到约 2.25:1，低于 AA），仍可预配置。
- `laya_review` / `multimodal_only` 且 baseUrl 或模型名任一为空时，出 `primarySoft` 底 + `warn` 描边的
  提示块：**这一档需要能看图的模型，还没配置时分数会退回本地模型的判断**——不写含糊的"未配置"。
- Key 与决策模型的 Key **分开存**（`visionApiKey`），明文 / 钥匙串提示复用同一套 `keySecure` 文案。

**结果页 · 结论来源标注**（`engine-badge`，数据来自本次运行的 `flow.quick.*`）

| `flow.quick.engineMode` | 徽标文案 |
|---|---|
| `laya_only` | 本地模型判断 |
| `laya_review` | 本地模型 + 多模态纠正 |
| `multimodal_only` | 多模态模型判断 |
| 引擎未回报 | 结论来源未标注 |

- **不拿当前设置顶替**：用户跑完再改设置时，用 config 当前档位会让历史结论说谎。
- `reviewFailed === true`：徽标描边转 `warn`，旁注 **纠正未生效，显示的是本地模型判断**（§3.9c 回退约定，陈述事实）；
  `reviewErrorKind === 'vision_unconfigured'` 时旁注改为 **还没配置能看图的模型，显示的是本地模型判断**，
  并给「去设置页」入口（44px 触达）。
- 纠正生效（`reviewFailed !== true` 且 `reviewChange` 非空）：徽标右侧一行 **已按画面重新判断**。
- **不显示任何分数差值**：用户要知道"结论来自谁"，不需要看两个模型差了几分。

### 4.6 设置页顺序与「视觉先行」闸门（v1.6）

**版面顺序改回因果顺序**：① 引擎模式 → ② **能看图的模型** → ③ **决策模型**。
架构是「Laya 本地模型打分 → 能看图的模型纠正」，**没有能看图的模型，纠正环节根本不存在**，
用户拿到的就是实测判断力不合格的本地分（得体 vs 荒谬的面试穿搭综合分只差 0.4）。
把视觉组放在决策组之前 = 让"先保证结论可用"这件事在版面上可见。

**「视觉已就绪」的两条路径**（`visionReady`）

| 路径 | 判据 | 状态标记 `vision-readiness` |
|---|---|---|
| 自己填 | `visionBaseUrl` 与 `visionModel` trim 后都非空 | 已就绪 |
| 服务端已配 | 勾选 `vision-server-side`（`visionServerSide: true`，随 `od.config.v1` 持久化） | 服务端已配置 |
| 都没有 | — | 未配置 |

- 服务端开关的文案逐字：**能看图的模型已配在服务端（如本机 Laya 适配器），无需在此重复填写**；
  副文案逐字：**勾选后若服务端其实没配置，结果页会提示「纠正未生效」——那说明这个开关该取消。**
  本机 Laya 适配器（`tools/laya-adapter.mjs`）已在服务端 `.env.local` 配好视觉模型，
  直连它的用户不该被逼在手机里再填一遍 Key；两条路径都真的解锁，**不是**二选一的死路。
  勾错不会有别的即时反馈，所以把"退化时你会看到什么信号"直接写进副文案（结果页的
  `reviewFailed` 旁注就是那个信号），而不是再加一道验证。
- 状态标记配色只用既有令牌：`success #4F6B3C` on `surfaceAlt #EFE7DA` = 4.89:1（已就绪 / 服务端已配置），
  `textDim #6B6154` on `surfaceAlt` = 4.94:1（未配置）——都过 AA 小字 4.5:1。

**闸门按档位条件化**：`gateActive = needsVision && !visionReady`、`decisionLocked = gateActive && !decisionUnlocked`，
其中 `needsVision = engineMode !== 'laya_only'`（与 `src/engine/orchestrator.js` 的运行时分档一致，
未知档位在运行时按默认档处理）。

| 档位 | 需要视觉模型 | 未配视觉时决策组 |
|---|---|---|
| `laya_only` | 否（不纠正、describe 走本地通道） | **不锁**，纯本地模式照常可用；视觉组挂着「当前档位用不到这一组」 |
| `laya_review`（默认）/ `multimodal_only` | 是 | 默认锁住，直到视觉就绪**或用户显式临时解锁** |

- **顺序要求不该以一整档不可用为代价**：`laya_only` 锁决策组是硬伤，所以闸门只在该档之外生效。
- 切换档位立即生效：`laya_only → laya_review` 且视觉未配 → **立刻重新上锁**、提示块回来。

**禁用必须能绕开**：视觉端点本身坏掉（Key 错 / 服务不通 / 模型下线）时，用户还得能配一个可用的决策模型，
否则 App 变砖头——而那正是最需要配 fallback 的时候。所以提示块里给了显式临时解锁：

| 动作 | testID | 文案 |
|---|---|---|
| 去配置（主推） | `decision-gate-jump` | 去配置 |
| 仍然配置决策模型（逃生口） | `decision-gate-unlock` | 仍然配置决策模型 |
| 恢复按顺序配置（解锁后） | `decision-gate-relock` | 恢复按顺序配置 |

- 点 `decision-gate-unlock` → `onChangeConfig({ decisionUnlocked: true })`：决策组**立即解锁且可保存 Key**
  （`od.apikey.v1` 必须真的落盘，这是被硬禁用挡掉的门禁路径）。
- 解锁后 amber 提示块**换成弱说明** `decision-gate-unlocked-note`（`surfaceAlt` 底 + `border` 描边 +
  `textDim` 字 4.94:1，不是警告语气）：**已解锁决策模型。没有能看图的模型时，你看到的只是本地模型的判断。**
- `decisionUnlocked` 随 `od.config.v1` 持久化；视觉配好或勾了服务端时 `gateActive` 变 false，该标记**自动失效**
  （公式直接把它旁路掉，不额外写回；若之后又把视觉清空，之前勾过的解锁会重新生效——这是公式的既定行为）。
- 两条放行开关并存不冲突：`vision-server-side` 表达"服务端已配"（事实），`decisionUnlocked` 表达"我知道有风险，先配"（临时）。

**需要用视觉模型的档位 + 未就绪 + 未临时解锁时，决策模型整组不可操作**

- 输入框挂**真正的 `disabled` 属性**（不是只把颜色调灰）：`editable={false}` + `aria-disabled` +
  `accessibilityState={{ disabled: true }}`，web 上再补 `disabled`（RN-web 的 TextInput 会把它透传到 `<input>`），
  键盘与点击都改不动值。按钮与「决策模型来源」两张卡片同样 `disabled` + `aria-disabled`。
- 禁用态**不降透明度**（55% 会把标签压到约 2.25:1，低于 AA）：输入框换 `surfaceAlt` 底 + `border` 描边 +
  `textDim` 文字（4.94:1），按钮同理；决策组标题降为次级墨色（5.39:1）并挂一枚 `primarySoft` 底
  `warn` 字的「未解锁」标记（`warn #8A5A12` on `primarySoft #F6E7CF` = 4.86:1）。选中的来源卡片也换成
  `surfaceAlt`（`text` 字 13.48:1），否则墨色实心会看起来"还能点"。
- 视觉区**不受影响、始终可编辑**（否则用户死锁在闸门里）。

**闸门提示块**（`decision-gate-hint`，`primarySoft` 底 + `warn` 描边，复用视觉组提示样式，位于决策组正上方）

> 先配好能看图的模型，再配决策模型。没有它，纠正环节不会生效，你看到的只是本地模型的判断。

块内两个 44px 动作并排：`decision-gate-jump`（「去配置」，warn 描边）滚动到视觉区并聚焦 baseUrl，
不让用户自己在长表单里找；`decision-gate-unlock`（「仍然配置决策模型」，中性描边 + 墨色字）是逃生口。
视觉就绪即整块消失（不是常驻横幅）。

**决策模型组副标题**：**负责打分。它在纠正之前运行，所以视觉模型要先配好。**

| 要求 | 做法 |
|---|---|
| 44px 最小触达 | 所有 `Pressable` / chip / 行内按钮 `minHeight: 44`（`HIT`） |
| 底部主 CTA | 上传页 CTA 固定在 `ScrollView` 之外的底部坞里（`PrimaryButton`，56px） |
| SafeArea | 根部 `SafeAreaView edges={['top']}`；底部坞与各列表用 `useSafeAreaInsets().bottom` 做 `max(inset, 16)` 内边距 |
| **CTA 不遮挡内容（第 2 条修正）** | CTA 坞与 `ScrollView` 是**并列的 flex 兄弟节点**，不是浮层：滚动内容 100% 能滚进 CTA 上方，不存在被压住的情况；内容底部另留 `space.xl` |
| 横向 chips | `ChipRow` = 横向 `ScrollView`，负边距让它能滚到屏幕边缘；横向不换行 |
| 长列表 | 历史用 `FlatList`，其余页面用 `ScrollView` |
| 键盘 | 上传页与设置页外层 `KeyboardAvoidingView`（iOS `padding`），`keyboardShouldPersistTaps="handled"` |
| 中文多行 | 正文 15/21、说明 13/20、标签 11/16，长文案不靠缩小字号塞进一行 |

## 6. 动效（`motion` = 150 / 250 / 400ms）

只有三处，幅度克制，不抢读数的位置：

1. **chip 选中**（`fast 150`）：底色从纸面切到墨色，`opacity` 按下反馈 0.72。
2. **进度卡**（`ProgressCard`）：每套一个方块点，`describing` 完成一套点亮一格——把"AI 在工作"
   按套展开成看得见的进度，而不是一个转圈。
3. **卡片抬起**（`base 250`）：排名第 1 的卡片换成 `shadow.lift`、描边转 `accent`、挂上「今天穿这套」吊牌。

## 7. 被删掉的文字（减法）

- `最多 4 套，选满为止` → `已选满 4 套（上限 4 套）`／`还能再加 N 套`（第 5 条修正：不再暗示还能加）
- `4 LOOKS LOADED` / `SESSION 08:10` / `SYSTEM ONE` / `用时 9.2s` 等仪器式英文与假读数**全部不采用**
  （第 3 条修正：界面不出现像实测的编造读数；「约 10 秒」是明确标注的估算；
  连接测试显示的耗时是当次请求的真实测量值）
- 首屏的 `今天穿哪套？` 之外没有第二句解释性文案；CTA 下方只留一行 `只出分数，不出解释 · 约 10 秒`
- 未使用任何 Emoji、渐变按钮、装饰插画

## 8. 未做与已知缺口

- 未做深色主题：方向 B 的深色底未被采用（早上户外可读性 + 用户语气）。
- 未做图表化六维雷达图：软尺刻度已能表达读数，雷达图在这个尺寸下不可读。
- 组件级自动化测试不做（SPEC §8 非目标）；验证走 web 端到端冒烟。
